# 2026-06-23

## Added `dummy-model` standalone test/demo backend

New binary `cmd/dummy-model` serves an OpenAI-compatible endpoint backed by a fake model — no real inference, deterministic output — so tests and demos don't need Ollama/vLLM/OpenAI/etc. or network egress.

- `server.go` holds a `server` struct + handlers; `main.go` is a cobra single-root command mirroring `cmd/llm-gateway`. Logging via `df/dl`, plain `net/http` mux with Go 1.22 method-pattern routes.
- Reuses the `providers` package wire types, `SSEWriter`, and error helpers verbatim — nothing re-declared. This keeps the dummy's output identical to what the gateway expects from a real backend.
- Features: echo (default) or `--response` canned text; `/v1/models` + `/health`; streaming with `--stream-delay`; tool-call simulation when a request carries `tools`; `--error-rate`/`--error-type` error injection. Default listen `:8081` (avoids the gateway's `:8080`).

### Gateway integration (no gateway code changed)
The gateway routes any non-`gpt-*`/`o1-*`/`o3-*`/`claude-*` model to its `local` provider, which calls `<base_url>/v1/chat/completions` (`providers/local.go:52`). So pointing `providers.local.base_url` at the dummy makes it a drop-in backend. Verified end-to-end: gateway routed `llama3` → local → dummy and returned the echoed reply.

### Notes / gotchas
- Non-streaming tool-call responses serialize `"content":null` (Message.Content is `any`, json tag has no omitempty) — this is OpenAI-correct for tool calls, not a bug.
- `httptest.ResponseRecorder` implements `http.Flusher`, so `providers.NewSSEWriter` works in tests without a real server.
- This is the first entry under `docs/journal/` for this repo (agent-memory convention).

## Agora layer-1 redux implemented (`agora/` package + gateway wiring)

Implemented the spec+work-order in `docs/future/agora.md` / `agora-work-order.md` (converged through 4 mercurius rounds). New top-level `agora/` package mirrors mcp-gateway's, plus gateway config/bootstrap/Run/cleanup wiring. Code complete; full suite + `-race` green.

### Load-bearing decisions (rationale not visible in the diff)
- **Bind-only serve is the one deliberate divergence from mcp-gateway** (which is create-or-bind). `agora/serve.go` was written fresh: no `Create`/`Delete` in the `agoraOps` interface or `defaultOps`, no `managed` flag. The gateway binds an operator-provisioned direct tcp-mode tunnel and never creates/deletes it — this deletes the create-race / leak-on-crash / ephemeral-grant foot-guns. Provisioning lives in the `agora tunnel create/delete` CLI, operator-side. Do **not** "restore" a create path to match mcp-gateway.
- **`Config.AgoraPublishEnabled()` requires serve** (`AgoraServeEnabled() && AdvertisementPublish`), unlike mcp-gateway's serve-independent publish. A dial-only gateway must never publish an advertisement whose name is a front-door tunnel it doesn't bind. Explicit `advertisement.publish: true` with serve off is a *boot error* (via the exported `agora.PublishExplicit`), not silent suppression — that's why `publishExplicit` was exported.
- **Provider wiring never rewrites `base_url`** (agora branch mirrors zrok: pass-through). This is load-bearing for cloud egress — the transport sets `DialContext` (not `DialTLSContext`), so the provider layers TLS *over* the agora conn with correct SNI/Host and TLS is end-to-end. An `http://<tunnel>` sentinel would break it. Precedence is agora > zrok > direct (agora branch added *above* each zrok branch).
- **`collectAgoraTunnels` mirrors `initProviders`' init gates exactly** (OpenAI/Anthropic only when `APIKey != ""`; Local endpoint tunnels in multi mode, single `Local.AgoraTunnel` only in single mode) — so the dialer attaches exactly the set that gets wired, no phantom attachments. If you change an init gate, change both together.

### Dependency gotcha
- Pinned **agora `v0.1.5`** (Michael's call; released by github tag; carries the account-scoped bind relaxation). Adding it surfaced an **ambiguous-import**: `go.etcd.io/etcd/api/v3@v3.5.0` drags in the pre-split monolithic `google.golang.org/genproto@2021`, which still contains `googleapis/rpc/*` and collides with the split `genproto/googleapis/rpc` that grpc v1.79.2 needs. Fix was bumping monolithic genproto to a post-split version (`@v0.0.0-20260209...`) + grpc to `v1.79.2` (matching mcp-gateway), then `go mod tidy`. If a future dep bump reintroduces old genproto, this is why.
